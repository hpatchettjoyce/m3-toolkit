# Brand palette — extracted from `M3 Branding Guide.pdf`

Generated by `python3 dextrous/extract_brand_palette.py` (re-run it to verify).
Source: page 15, "MONUMENTUM — COLOR PALETTE". **Every one of the 18 swatches has an RGB value that
matches its printed hex exactly (18/18)**, so these values are read from the guide, not sampled.

## The palette

The page lays swatches out 6 to a row. Only the top row is labelled by name in the guide; the row
groupings below are **inferred from that layout** — the hex values are fact, the row names are not.

| | Wine | Gold | Green | Teal | Dark | Light |
|---|---|---|---|---|---|---|
| **Primary** (named) | `#34050D` RED WINE | `#E4A557` GOLD STONE | `#17270B` BASIL LEAF | `#102A2A` DEEP WATER | `#041212` OFF-BLACK | `#F8F3E6` OFF-WHITE |
| **Accent** | `#730B1D` | `#DEBA87` | `#4D541A` | `#5CA7A8` | `#374141` | `#FBF8F0` |
| **Light** | `#C89583` | `#F1E3CE` | `#B7BA9F` | `#B1C7C8` | `#999F9F` | `#FEFDFA` |

Page 8 of the guide carries the headings `PRIMARY BRAND COLORS`, `ACCENT COLORS`,
`LIGHT BRAND COLORS` and `NEUTRAL COLORS` — four groups across three rows, so "Dark"/"Light" above
are most likely the NEUTRAL column rather than a fourth row. Worth a glance at the page before
naming the CSS tokens.

## What this gives Chunk 6

- **The off-black ground the chunk asks for is `#041212` (OFF-BLACK).** `#374141` and `#999F9F` are
  the natural panel and border steps above it; `#F8F3E6` (OFF-WHITE) is the body text colour.
- `#E4A557` (GOLD STONE) is the obvious accent — it is the only high-chroma, high-luminance colour
  in the set and reads well on the off-black.

## Dominion colours — ANSWERED 2026-09-15

The guide gives four chromatic hues but the game has six dominions, so the mapping was never
derivable from it. Harvey supplied all six directly, in `Dominion Colours.txt`:

| Dominion | Hex | On white paper |
|---|---|---|
| Rhavlika | `#DD2335` | 4.81:1 |
| Iro-Si-Khar | `#28A9D9` | 2.70:1 |
| Voisira | `#F7B828` | 1.77:1 |
| Xalakith | `#EDE9DC` | 1.21:1 |
| Ahèserec | `#29A049` | 3.38:1 |
| Veritian | `#464C68` | 8.42:1 |

**These were chosen to sit on the off-black ground, but in the web tool they only ever appear as ink
on white card stock** — `FACTION_COLORS` is referenced in exactly one place, `generatePrintCard`.
Three of them do not survive that: the print grid butts cards together with no gap, so a card's
border is the line you cut along, and Xalakith at 1.21:1 is a white line on white card.

So `FACTION_PRINT_OVERRIDES` in `CastRecruiter.html` darkens exactly those three — `#24A0CE`,
`#C48A07`, `#A69356` — hue and saturation preserved, to clear 3:1. The other three print as
supplied. Harvey chose this over using them verbatim or giving every card a neutral outline.

`dextrous/check_theme_contrast.py` asserts all six on paper, so this cannot regress silently.

## Fonts — ANSWERED (Chunk 7, 2026-09-15)

Embedded in the guide: `Cinzel-Medium`, `Avenir` (Black / Medium / Book, with obliques),
`ArbanePixel` (Regular / Outline), `AldaOTCEV-LightItalic`, `TimesNewRomanPSMT`.

**Only Cinzel is a brand face, and only for display type.** PG.07 is titled "MONUMENTUM - Logo
Typography", labels its single specimen "LOGO TYPEFACE", and shows **Cinzel Medium** with a full
A–Z / a–z / 0–9 setting. No other face appears on that page, and the guide specifies no body face
at all.

The rest are the *presentation deck's* own fonts, not the brand's. The font resource map settles it:

| Resource | Face | What it draws in the guide |
|---|---|---|
| `T1_0`, `T1_1` | ArbanePixel-Regular | page furniture — "PG. 07", "BEX VLE DESIGNS", dates |
| `TT0` | ArbanePixel-Outline | section headings, e.g. "LOGOMARK SAFE ZONE" |
| `TT1` | Avenir-Oblique | captions, e.g. "LOGO TYPEFACE", "Logo Safe Zone:" |
| `TT2` | Avenir-Medium | body copy, e.g. the file-format list |
| `C2_0` | TimesNewRomanPSMT | incidental |

So there is no brand body face to apply. Cinzel is OFL-licensed and served by Google Fonts, so it
needs no licence purchase and no self-hosted file. `CastRecruiter.html` uses it for `h1`/`h2` via
`--font-display`; body copy keeps its sans stack via `--font-body`.

To re-derive the resource map, the same zlib trick that reads the swatches also reads text and
`/BaseFont` entries — see `dextrous/extract_brand_palette.py` for the stream inflation.

## Reading the PDF on this machine

There is **no PDF tooling installed**: no `poppler-utils` (so no `pdftotext`, and Claude's PDF page
rendering fails with "pdftoppm is not installed"), no `pypdf`, no `pip`, and `apt-get` needs a sudo
password. `extract_brand_palette.py` works around this by inflating the PDF's own content streams
with `zlib` — no dependencies.

To read the guide *visually* (needed for layout, logo placement and Chunk 7), install:

```bash
sudo apt-get install -y poppler-utils
```

**Trap:** a bare `#[0-9A-Fa-f]{6}` regex over the inflated streams also matches byte sequences inside
the embedded font programs and invents colours that are not in the brand — `#532677` (a purple),
`#526557` and `#566557` all appear that way. The extractor anchors on the full `RBG:/CMYK:/HEX:`
triple the guide prints beside each swatch, which is why it returns exactly 18.
